# Журнал действий: обновление

## План

1. Единый словарь событий, позывных и полей; адаптер старых записей без миграции.
2. Читаемое сравнение изменений, фильтры и постраничный доступ ко всей истории.
3. Полнота событий приложения и исправление снимков, дат, ошибок и составных операций.
4. Регрессионные проверки и сборка. Никаких записей в рабочую базу при проверке.

## Совместимость и идентификация

Коллекция `logs` сохраняется. Существующие документы не обновляются и не удаляются.
Новые записи используют `schemaVersion: 2`, сохраняют прежние поля и добавляют
`eventType`, `outcome`, `operationId`, `context`, `references`.

`actor.uid` — UID аккаунта; `actor.playerId` — ID игрока; `actor.nickname` — позывной
на момент действия. Имя учётки используется, если позывной неизвестен. Автор и
затронутый игрок — разные роли. Сохранённые позывные имеют приоритет над текущими.
Текущая привязка старой записи помечается явно. Неизвестный игрок не называется удалённым.

Старые действия определяются по `metadata.operation`, типу сущности и снимкам.
Неизвестные события сохраняют исходный заголовок и JSON. Нельзя считать отсутствие
снимка доказательством отсутствия объекта. Недостающие исторические сведения не выдумываются.

## Покрытие

| Источник | События |
| --- | --- |
| Игроки | создание, редактирование полей, мягкое и полное удаление |
| Пользователи | создание аккаунта, изменение роли, автоматическая роль, привязка и отвязка |
| Расстановка | добавление/удаление слота, набор слотов, назначение/перемещение/снятие, снаряжение, группа, тип, заметки, задачи, метаданные |
| Запросы | создание, изменение, удаление, очистка, старый встроенный формат |
| Посещаемость | отметка игрока, пресеты, дата, очистка, пропуск и снятие пропуска |
| Неделя | закрепление дат, завершение, пропуск, очистка; общий ID операции |
| Архив и ротации | архивация игры, создание/изменение/удаление ротации |
| Шаблоны | создание, изменение, удаление |
| Настройки | сайт, отряд, справочники, описание и награды |
| Telegram | пять назначений сообщений; успех, ошибка, пропуск отправки |

Чтение данных, переключение вкладок и локальный кэш статистики не являются
изменениями предметных данных и не засоряют журнал действий. Автоматическое
обновление `lastLoginAt` не считается отдельным изменением профиля.

## Границы

Журнал клиентских действий не является серверным аудитом всех записей Firestore.
Локальное расширение `DeltaOpsParsing` и административные скрипты пишут напрямую,
минуя приложение. Для гарантированного аудита этих источников нужен доверенный
серверный обработчик либо авторизованный производитель событий. Нельзя выдавать
наблюдение клиентом за чужой записью за действие текущего пользователя.

Правила `logs` должны разрешать только создание с собственным UID автора;
обновление и удаление через клиент запрещены. Изменения правил в репозитории
требуют отдельного развёртывания. Серверные административные права правилами не ограничены.

## Проверки перед выпуском

- Старые и неизвестные события, переименованные/удалённые/неизвестные игроки.
- Отсутствующие снимки, вложенные изменения, перестановка слотов, false/0/null.
- Быстрые изменения, сбои записи/удаления и отправки Telegram.
- Старые даты после завершения недели, частичное выполнение и повторная архивация.
- Пагинация, повторная загрузка, ошибка чтения, уход со страницы во время запроса.
- Фильтры работают по загруженным страницам; это явно указано в интерфейсе.
